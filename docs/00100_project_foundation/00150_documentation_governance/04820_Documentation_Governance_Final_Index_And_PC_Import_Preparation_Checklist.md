04820 Documentation Governance Final Index And PC Import Preparation Checklist

\#\# 1\. Purpose

This document defines the final index, PC import preparation checklist, documentation governance closure point, and transition rule for the Yoonsul Wait/Order Handoff documentation governance series.

The project has established a mobile-first, documentation-first workflow.

Documents may be drafted on mobile, stored temporarily in Google Docs, imported into the PC repository later, normalized by filename, sorted into folders, indexed, cross-referenced, reviewed for duplicates, and tracked through readiness dashboards.

This document closes the current documentation governance block and prepares the project for PC-side import and organization work.

\#\# 3\. Core Principle

Documentation governance must be ready before the document corpus is imported at scale.

The project must follow this rule:

\> Before moving many mobile-generated drafts into the repository, the import, naming, indexing, duplicate, and readiness rules must be clear.

A large import without governance creates confusion.

A large import with governance creates a controlled design corpus.

\#\# 7\. Pre-PC Import Checklist

Before importing mobile drafts into the repository, confirm:

\- Google Docs drafts are grouped or identifiable.
\- Each draft has document number.
\- Each draft has H1 title.
\- Each draft has final conclusion section.
\- Mobile copy did not truncate the document.
\- No nested code fence broke the draft.
\- No writing block marker remains.
\- No real secret exists.
\- No raw CI / DI exists.
\- No production payment data exists.
\- Draft status is known where possible.
\- Last generated document number is known.
\- Current lane is known where possible.
\- Incoming repository folder is ready.
\- Index update plan exists.
\- Directory map update plan exists.
\- Cursor review prompt is ready.

If these items are not ready, import should proceed in smaller batches.

\- H1 titles
\- filenames
\- folders

\---

\#\# 13\. First PC-Side Cursor Review

The first PC-side Cursor review should not implement anything.

Recommended first review task:

    TASK:
    Review imported Markdown drafts only.
    Do not implement code.
    Do not rewrite document bodies.
    Do not delete or merge files.
    Check filenames, H1 titles, document numbers, duplicate candidates, folder placement, index gaps, directory map gaps, and mobile artifacts.
    Return a safe review report and recommended next actions.

The first review should establish document health, not modify architecture.

\---

\- Flutter screens

\- payment integration
\- CI / DI integration
\- POS/KDS integration

\#\# 15\. Filename Preparation Checklist

Before final placement, check each file:

\- filename starts with document number
\- filename reflects H1 title
\- filename uses underscores
\- filename ends with \`.md\`
\- filename has no unsupported characters
\- filename does not include temporary Google Docs wording
\- filename does not duplicate another active file
\- filename type suffix is clear where useful

Filename can be changed later, but document number must remain traceable.

\---

\#\# 16\. H1 Preparation Checklist

Each file must have:

\- one H1 title
\- H1 starts with document number
\- H1 title matches intended document title
\- no duplicate H1
\- no missing title
\- no unrelated assistant preface inside H1
\- no Google Docs metadata inside H1

H1 title anchors the document identity.

\---

\#\# 17\. Folder Placement Preparation Checklist

Before moving files into final folders, check:

\- lane is known
\- document type is known
\- folder purpose matches document content
\- high-risk security documents are grouped clearly
\- SOPs are separated where useful
\- implementation mappings are separated from policies
\- test catalogs are separated from policies
\- evidence registers are separated from policies
\- obsolete drafts are not placed in active folders

Folder placement should support future AI-assisted implementation.

\---

\#\# 18\. Index Preparation Checklist

Before index update, check:

\- document number
\- title
\- filename
\- folder path
\- lane
\- document type
\- status
\- related documents
\- readiness status where applicable

Index should not include unreviewed drafts as active.

Unreviewed drafts may be listed as \`NEEDS\_REVIEW\`.

\---

\#\# 19\. Directory Map Preparation Checklist

Before directory map update, check:

\- actual folders exist
\- folder purpose is defined
\- document range is understood
\- folder status is known
\- incoming folder is marked temporary
\- archive folder is marked inactive
\- implementation mapping folder is separate where useful
\- SOP folder is separate where useful
\- testing folder is separate where useful
\- evidence folder is separate where useful

Directory map must reflect real folder structure.

\---

\#\# 20\. Duplicate Review Preparation Checklist

Before duplicate cleanup, check:

\- duplicate document numbers
\- similar titles
\- near-identical Purpose sections
\- near-identical Scope sections
\- repeated readiness checks
\- policy/SOP overlap
\- policy/mapping overlap
\- old draft versus final version
\- Google Docs repeated import
\- same document copied into different folders

Duplicate review should produce candidates before destructive action.

\---

\#\# 21\. Obsolete Archive Preparation Checklist

Before archiving a document, check:

\- active replacement exists
\- content is actually obsolete
\- unique constraints are not lost
\- patent/IP relevance is considered
\- cross-references are updated or queued
\- index status is updated
\- archive filename is clear
\- top-of-file obsolete note is added where useful

Archive is safer than deletion during documentation phase.

\#\# 24\. Google Docs Cleanup After Import

After successful import, Google Docs drafts should be marked.

Recommended markers:

\- \`IMPORTED\_TO\_REPO\`
\- \`IMPORTED\_IN\_BATCH\_{batch\_id}\`
\- \`DUPLICATE\_CANDIDATE\`
\- \`MERGED\`
\- \`OBSOLETE\`
\- \`DEFERRED\`
\- \`NEEDS\_PC\_REVIEW\`

Google Docs should not remain the only place where important documents exist.

\---

\#\# 25\. Commit Preparation Checklist

Before committing a batch, confirm:

\- files are in expected folders
\- filenames are normalized or intentionally temporary
\- H1 titles are correct
\- no duplicate document numbers remain active
\- no secrets exist
\- no raw CI / DI exists
\- no implementation code was added
\- index is updated or queued
\- directory map is updated or queued
\- batch report exists for medium or large batch
\- commit message uses documentation prefix
\- changes are reviewable

Commit should preserve traceability.
