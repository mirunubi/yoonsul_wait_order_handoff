## 작성 규칙

- 실제 구현 결과만 기록하며 계획이나 예상 결과를 완료 사실처럼 표현하지 않는다.
- 연계 Logic의 ChangeContract와 실제 변경 범위를 대조한다.
- 변경 파일마다 변경 목적과 검증 근거를 기록한다.
- 불변조건 및 수용 기준별 통과 여부를 추적 가능하게 작성한다.
- 테스트 명령, 결과, 증거 경로를 재현 가능한 형태로 남긴다.
- 미검증 항목이나 실패 항목이 있으면 완료 판정을 보류하고 사유를 적는다.
- Module 문서가 없으면 구현 완료로 판정하지 않는다.
- Status, Owner, Last Updated는 문서 변경 시 함께 갱신한다.
