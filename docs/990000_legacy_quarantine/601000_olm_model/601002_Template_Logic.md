## 작성 규칙

- 연계 Overview의 요구사항과 불변조건을 누락 없이 구체화한다.
- 정상 흐름, 실패 흐름, 재시도 및 복구 흐름을 각각 작성한다.
- 입력, 출력, 상태 변화 및 부작용을 명확히 정의한다.
- 구현 허용 파일과 변경 금지 파일을 ChangeContract에 명시한다.
- TestPlan은 수용 기준 및 불변조건과 추적 가능해야 한다.
- 의사코드는 구현 언어와 혼동되지 않도록 코드 블록의 성격을 표시한다.
- Status, Owner, Last Updated는 문서 변경 시 함께 갱신한다.
