## 작성 규칙

- 구현 상세보다 문제, 목표, 경계 및 전체 흐름을 중심으로 작성한다.
- 범위와 비범위를 명시적으로 분리한다.
- 불변조건은 추적 가능한 식별자(예: `INV-001`)를 부여한다.
- 확정 사실, 가정, 미결정 사항을 구분한다.
- 모든 주요 요구사항은 Logic 및 Module 문서에서 추적할 수 있어야 한다.
- Status, Owner, Last Updated는 문서 변경 시 함께 갱신한다.
