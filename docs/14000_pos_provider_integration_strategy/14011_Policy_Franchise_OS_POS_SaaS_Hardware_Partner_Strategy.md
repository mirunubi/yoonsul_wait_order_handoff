# 14011_Policy_Franchise_OS_POS_SaaS_Hardware_Partner_Strategy

## 1. Purpose

This document defines the long-term strategy for linking Yoonsul Wait/Order Handoff, Mini Kiosk, Kiosk, POS provider gateway, KDS, and Franchise OS into a SaaS-based store operation platform.

The project does not aim to compete with incumbent POS providers only at the payment terminal or order input layer.

The long-term competitive advantage is expected to come from:

- operation OS integration
- franchise OS integration
- store runtime data
- handoff automation
- KDS continuity
- payment/order reconciliation
- staff/workforce linkage
- inventory and sold-out linkage
- customer membership and repeat-order linkage
- support/recovery/audit evidence
- SaaS monthly revenue
- hardware partner ecosystem
- provider gateway leverage

This document records the strategic view that once Franchise OS is mature, the project can compete with ledger-centered POS incumbents through software advantage.

This document does not implement Franchise OS, POS, kiosk, payment, hardware, SaaS billing, or provider integration.

It defines strategic direction only.

## 3. Core Strategic View

The project’s real competitive power is not the kiosk itself.

The project’s real competitive power is:

    Kiosk / POS / KDS / Payment / Staff / Inventory / Customer / Franchise OS integration

A kiosk without operation OS is a device.

A POS without Franchise OS is a ledger.

A payment terminal without operational intelligence is a fee channel.

Yoonsul should compete by connecting these into one operational SaaS runtime.

---

## 4. Strategic Thesis

The strategic thesis is:

> Existing POS providers are strong in transaction ledger, device distribution, VAN/dealer relationships, and installed base. Yoonsul can win software leverage by connecting wait/order handoff, Mini Kiosk, KDS, store operation OS, and Franchise OS into a SaaS platform.

This is not a short-term replacement strategy.

It is a staged expansion strategy.

## 8. OKPOS Competitive Position

OKPOS is strong because:

- installed base is large
- store owners and dealers are familiar with it
- POS ledger is stable
- payment/VAN/printer/kitchen setup is already common
- many stores do not want to migrate POS
- table order and kiosk integration paths may exist through OKDC or partners

But OKPOS is primarily ledger and POS infrastructure centered.

Yoonsul should not try to beat OKPOS first by replacing every POS terminal.

Yoonsul should first connect above and around it.

---

## 9. Toss Competitive Position

Toss is strategically attractive because:

- it is more cloud/API friendly
- it is flexible for modern integration
- it may want to gain share against incumbent POS providers
- it can be a better base for Yoonsul’s first implementation
- it aligns with SaaS-style backend control
- it may support modern Mini Kiosk and provider gateway direction

Yoonsul should remain:

    Toss-first, but not Toss-locked.

## 11. Hardware Partner Strategy

Yoonsul does not need to become a hardware manufacturer first.

Recommended strategy:

    Build software runtime.
    Prove store operation value.
    Partner with hardware vendors when rollout requires devices.

Hardware partner candidates may include:

- kiosk hardware manufacturer
- tablet provider
- POS terminal vendor
- printer/scanner vendor
- payment terminal distributor
- local installation partner
- VAN/POS dealer network
- white-label hardware supplier

Yoonsul should own:

- runtime logic
- provider gateway
- Mini Kiosk software
- KDS/handoff policy
- SaaS account
- audit/recovery
- Franchise OS linkage

Hardware partner should supply:

- device
- installation
- maintenance
- certified hardware path
- local support where needed

---

## 12. Hardware Partnership Timing

Hardware partnership should not be rushed.

Recommended timing:

| Stage | Hardware Strategy |
| ----- | ----------------- |
| First store | Use available commercial hardware and vendor devices |
| Early test stores | Compare Toss/OKPOS/kiosk vendor hardware behavior |
| Operation OS stabilization | Define required hardware profiles |
| Franchise OS test | Identify repeatable hardware kit |
| SaaS expansion | Partner with hardware supplier for standardized rollout |
| Franchise rollout | Offer certified hardware package and SaaS bundle |

Hardware should follow software architecture.

Software should not be trapped by hardware vendor limitations.

## 16. Why POS Providers Become Vulnerable

Ledger-centered POS providers may become vulnerable when stores want:

- real-time operation optimization
- staff workflow visibility
- menu/sold-out automation
- KDS integration
- customer recovery
- franchise governance
- SaaS dashboard
- AI-assisted support
- provider-neutral integration
- multi-store rollout
- evidence-based operations

A POS ledger alone cannot easily own all these layers.

Yoonsul can compete by being the operational layer above the POS.

## 17. Strategic Wedge

The initial wedge should not be:

    Replace all POS providers.

The initial wedge should be:

    Improve order handoff, Mini Kiosk readiness, KDS continuity, payment recovery, and operation visibility around existing POS/payment providers.

Then expand into:

    Franchise OS + SaaS + provider gateway + hardware partner bundle.

This reduces resistance.

## 25. Mitigation Strategy

Mitigations:

- keep provider-neutral core
- use Toss as base but preserve OKPOS compatibility
- phase provider expansion
- avoid premature hardware commitment
- create evidence before rollout
- keep payment truth secure
- separate payment revenue from payment authority
- define rollback for each provider
- test locally before franchise rollout
- use hardware partners after runtime is stable
- keep SaaS pricing modular

## 29. Anti-Patterns

The following are prohibited:

- trying to beat OKPOS only at POS ledger level
- becoming a hardware company before software moat exists
- relying on payment margin before legal/provider review
- letting Toss define all Yoonsul architecture
- ignoring OKPOS installed base
- treating small kiosk vendors as strategic platform
- building SaaS pricing before value is proven
- expanding to 30 POS vendors before first runtime evidence
- mixing payment revenue interest with unsafe payment authority
- sacrificing recovery/audit for faster rollout

## 32. Conclusion

Yoonsul’s long-term competitiveness is not simply POS, payment, kiosk, or hardware.

The competitive advantage comes from operation OS and Franchise OS integration.

The strategic path is:

- use Toss as the flexible first base
- preserve OKPOS compatibility for market access
- build provider gateway and canonical runtime
- prove Mini Kiosk / KDS / payment recovery in real stores
- link store runtime to Franchise OS
- package the system as SaaS
- partner with hardware vendors after software value is proven
- pursue payment-related margin only within legal/provider-safe boundaries
- use SaaS monthly fee as the long-term cashflow foundation

Around the time Franchise OS becomes tested and stable, Yoonsul may be able to compete against ledger-centered incumbent POS providers through software leverage rather than hardware distribution power.

This document records that strategic direction for future development and business planning.
