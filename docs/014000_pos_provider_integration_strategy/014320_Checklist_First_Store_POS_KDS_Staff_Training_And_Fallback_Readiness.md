# 014320_Checklist_First_Store_POS_KDS_Staff_Training_And_Fallback_Readiness.md

## 1. Purpose

This checklist defines first-store staff training and fallback readiness for manual POS entry, manual KDS/kitchen handoff, payment/order separation, and daily reconciliation.

It is used before the first store operates Catch & Order in manual or semi-manual mode.

The goal is to ensure that staff can safely operate even when POS provider integration is unavailable, delayed, degraded, or intentionally disabled.

## 2. Core Rule

The first store may not activate Catch & Order order handoff unless staff can complete manual fallback.

Manual fallback is not optional.

It is the baseline operating mode until official POS/KDS/payment integration is approved.

## 3. Readiness Status

| Status | Meaning |
|---|---|
| Not Started | Training or readiness not begun |
| In Progress | Training/check is ongoing |
| Ready With Conditions | Usable with listed limitations |
| Ready | Fully ready for first-store operation |
| Failed | Must not activate |
| Deferred | Not needed for current scope |

## 8. Customer-Facing Wording Training

Staff must use safe wording.

| Situation | Safe Wording |
|---|---|
| Order received but not entered into POS | 매장에서 주문을 확인 중입니다 |
| POS entry pending | 매장 입력 확인 중입니다 |
| POS entry confirmed | 매장에서 주문을 확인했습니다 |
| Kitchen handoff pending | 주방 전달 준비 중입니다 |
| Kitchen handoff confirmed | 주방에 전달되었습니다 |
| Payment unknown | 결제 상태를 확인 중입니다 |
| Refund requested | 환불 요청을 확인 중입니다 |
| Delay | 조리 상황을 확인 중입니다 |

Do not say:

- 결제 완료
- 환불 완료
- 주방 접수 완료
- POS 접수 완료
- 주문 완료

unless supporting evidence exists.

## 13. Readiness Gate

First-store manual fallback is ready only when:

1. POS environment is identified.
2. Staff can manually enter POS orders.
3. Staff can create kitchen handoff without KDS.
4. Payment/order separation rule is understood.
5. Duplicate prevention drill passes.
6. Sold-out/correction/cancel/refund scenarios are drilled.
7. Daily reconciliation owner is assigned.
8. Shift lead can resolve mismatch.
9. Customer-facing wording is safe.
10. Evidence capture is tested.

## 14. Failed Readiness Conditions

Do not activate if:

- staff cannot prevent duplicate POS entry
- staff cannot create kitchen handoff without KDS
- payment completion is assumed without evidence
- refund/cancel process is unclear
- no daily reconciliation owner exists
- no shift lead escalation exists
- manual note format is not understood
- customer-facing wording is unsafe
- manager does not accept fallback mode

## 15. Required Outputs

After completing this checklist, produce:

- staff training completion record
- fallback drill result
- store environment snapshot
- readiness gate decision
- unresolved training gap list
- daily reconciliation owner assignment
- support escalation contact list

## 16. Non-Goals

This checklist does not define:

- provider-specific API implementation
- automated KDS integration
- payment gateway operation
- settlement accounting
- full franchise training program

It only validates first-store POS/KDS manual fallback readiness.
