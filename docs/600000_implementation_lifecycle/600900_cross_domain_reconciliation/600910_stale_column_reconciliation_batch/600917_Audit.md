Both functions now correctly emit `'memo'`.
3. **This workpacket resolves `600423_Audit.md`'s carried-forward Open Items (e) and (f)** — the `o.request_memo` column error blocking `get_kds_realtime_state()` and the `case_severity`/`'INVESTIGATING'` double defect blocking `get_staff_alert_feed()`, both discovered during `600420`'s Stage 5 verification, are the exact two defects this batch fixes. Full E2E RPC execution for both functions — blocked since `600420` — is unblocked by this workpacket (subject to the newly found unrelated defects in Finding 5 below, which affect different functions).
4. `0133`'s phantom DDL correction was correctly treated as source-only (checksum updated, no live re-execution) — confirmed still no-op after `0015`, consistent with its design rationale.
5. Independent reproduction of `place_takeout_order()`, `health_check()`, and `get_reconciliation_report()` surfaced 3 out-of-scope stop points, none caused by this batch. Two are newly identified this workpacket (`health_check()`'s temp-table session lifetime, `place_takeout_order()`'s unassigned-record defect); the other two (`get_reconciliation_report()`'s `layer_number`/`amount_difference` for the 0084 4-param overload, `gap_amount` for the 0120 5-param overload) were already carried forward from `600912_Logic.md` §5.

## Open Items Carried Forward

(a) **`health_check()` (0092) — temp table session-lifetime mismatch (newly discovered this workpacket, structural defect).** The backing `pg_temp.health_check_items` table is created only by a top-level `CREATE TEMP TABLE IF NOT EXISTS` statement in the migration script (run once, at migration-apply time), not inside `health_check()` or `add_health_check_item()` themselves. Any fresh session invoking either function hits `relation "pg_temp.health_check_items" does not exist`. Unrelated to this batch's substitutions — candidate for a separate follow-up workpacket.

(b) **`get_reconciliation_report()` (0084, 4-param overload) — `layer_number`, `amount_difference` stale references.** Confirmed via direct reproduction: fails with `column "layer_number" does not exist` strictly after this batch's `severity`/`UNDER_INVESTIGATION` handling executes correctly. Carried forward from `600912_Logic.md` §5 (out of this batch's 3 replacement families).

(c) **`get_reconciliation_report()` (0120, 5-param overload) — `gap_amount` stale reference.** Real column is `0015`'s `amount_diff`. Carried forward from `600912_Logic.md` §5, not reproduced via a failing call this round (no test attempted against the 5-param overload specifically) but confirmed present in source via `grep`.

(d) **`place_takeout_order()` (0081) — `v_customer`/`v_coupon` unassigned-record defect (newly discovered this workpacket, structural defect).** Both `v_customer.id`/`v_coupon.id` are read via `is not null` checks before being unconditionally guaranteed an assignment, when the corresponding optional parameter (`p_customer_id`, `p_coupon_issue_id`) is supplied without the other — reproduced independently in two separate calls (guest path, then coupon-omitted path). Unrelated to `memo`; `p_memo` itself bound and passed correctly in both reproductions. Candidate for a separate follow-up workpacket.

(e) **`COMMITTED`/`READY_TO_COMMIT` status-name unification — still undecided.** Carried forward again from `600423_Audit.md` (d): awaiting external confirmation of whether `COMMITTED` appears in filed patent claim language (`900102`/`900160`/`900161`) before a final direction can be set. Not addressed in this batch.
