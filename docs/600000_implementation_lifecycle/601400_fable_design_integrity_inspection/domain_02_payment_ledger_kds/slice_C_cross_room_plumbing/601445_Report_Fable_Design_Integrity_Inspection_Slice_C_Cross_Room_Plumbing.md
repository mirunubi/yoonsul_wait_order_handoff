SQL grounding: `current_actor_id()` (0022:49) does correctly derive from `request.jwt.claims ->> 'sub'` server-side — the right primitive exists; the gap is the missing auth-user→`staff.id` mapping. 9.3 — Design Conflict Register
CRP-F03 — Append-only amendment mandate vs. the shipped mutable ledger; and the blind-spot catalog misses this exact risk. `DESIGN CONTRADICTION` · MEDIUM
010601 §5 requires "Internal ledger must be append-only where financial truth is involved"; §24 requires "Correction is not overwrite" with amendments recording before/after state; §34 anti-pattern: "amendment overwriting original record". The shipped `payment_ledger` is a single mutable row whose `cancelled_amount`/`refunded_amount`/`net_amount` accumulate via in-place `UPDATE`, producing no before-state. Aggravating finding: 010602 — the document whose entire purpose is naming blind spots — lists ten (`TIME_SYNCHRONIZATION_DRIFT` … `BATCH_REPORT_TAMPERING`) and misses this one. Its nearest item, `BATCH_AUDITOR_OVERAUTHORITY`, forbids the nightly batch from mutating source records (§19 "Batch must not silently update original financial truth") but says nothing about the transactional payment RPC path doing exactly that. It guards the back door and leaves the front door open. Secondary: two of 010601's four sources (`STORE_TERMINAL_POS_LEDGER`, `OS_RUNTIME_AUDIT_LOG`) have no counterpart in the current stack, so the "four-source closing audit" degrades to a two-source internal-vs-provider match, weakening §3's "No single source may finalize financial truth alone." Owner decision required: add an amendment/history table (sufficient — WORM not required by this layer), or formally accept mutable-in-place and amend 010601 §5/§24. Confidence: HIGH.

CRP-F01 — Webhook/provider-callback idempotency: correct policy, present infrastructure, unwired implementation. `IMPLEMENTATION DEFECT CANDIDATE` · HIGH — flagged separately per your request as the clean "정책은 옳고 구현이 문제" case.

CRP-F02 — Caller authorization: policy gap + implementation gap + architecture mismatch. `MISSING DESIGN CONTRACT` · HIGH
Detailed under cross-reference [#3](https://github.com/mirunubi/yoonsul_wait_order_handoff/issues/3) above. In short: the abstract rule exists (010641 §19) but was never translated into a Postgres-RPC-specific control — actor/staff id is never listed as tamperable, no session→staff resolution mechanism is named, `SECURITY DEFINER`/`auth.uid()`/JWT `sub` are never mentioned, and all three security docs model a gateway tier this stack does not have.
