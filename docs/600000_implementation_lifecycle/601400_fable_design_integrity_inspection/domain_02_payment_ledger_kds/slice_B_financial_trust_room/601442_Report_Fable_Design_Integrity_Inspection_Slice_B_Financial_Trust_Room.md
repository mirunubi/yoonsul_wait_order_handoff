9.3 — Design Conflict Register

The folder's ledger kernels mandate append-only, INSERT-only, version-sequenced, WORM/hash-chained, double-entry records and forbid direct DB mutation of financial records (010452 §25, 010454 §4, 010455 §16/§22). Both are self-marked deferred/planning, so this is not a binding-contract breach, but it creates a real canonical ambiguity for a money-layer: is the authoritative ledger design the deferred bank-grade WORM kernel, or the shipped mutable row? The MVP does not meet the financial-trust principles its own folder declares, and `kds_release_authorized` (the live payment→KDS gate) appears in none of these docs. Owner decision required: ratify the MVP mutable ledger as an accepted interim, and either schedule the WORM/double-entry kernel or retire it as canonical intent. Confidence: HIGH.
