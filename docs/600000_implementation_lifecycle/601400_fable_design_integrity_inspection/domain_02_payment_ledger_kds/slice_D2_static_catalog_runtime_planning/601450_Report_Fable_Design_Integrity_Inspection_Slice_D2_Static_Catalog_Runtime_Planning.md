9.7 — Runtime Risk Register
SCP-F02 — The refund pipeline is non-functional in four distinct ways and was never repaired. `RUNTIME BLOCKER CANDIDATE` / `IMPLEMENTATION DEFECT CANDIDATE` · HIGH
In `0098` (2026-06-21, defined once, never superseded):

1. `request_refund` transitions ledger → `REFUND_PENDING`, absent from `chk_ledger_status` → 23514.
2. It passes `p_decision := 'REFUND_PENDING'` to the audit record, absent from `chk_audit_decision` → 23514 (the PAY-F01 pattern from domain_01).

Aggravating: a third parallel refund engine (`refund_payment`, 0037) coexists. Mitigating: zero external callers for any of the three, so the breakage is latent — the same "0 callers" pattern as the takeout and kiosk RPCs. Owner decision required: widen `chk_ledger_status` to include the pending/failed states, or rewrite the refund pipeline to the existing 8-value vocabulary; and designate one canonical refund engine. Confidence: HIGH (constraint text and RPC bodies read directly).
