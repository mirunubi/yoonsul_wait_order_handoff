## BOM Discovery and Fix — `read_linked_project_ref()`

During implementation/verification, `supabase/.temp/project-ref` was found to carry a UTF-8 byte-order mark (BOM, `EF BB BF`) before the actual `upzthfwhtvazfftxnyfu` text — confirmed by direct byte inspection (`xxd`/Python `rb` read: `b'\xef\xbb\xbfupzthfw...'`). A plain `.read_text(encoding="utf-8").strip()` does **not** strip a BOM (`﻿` is not whitespace to Python's `str.strip()`), so the naive comparison `actual_ref == EXPECTED_PROJECT_REF` would have evaluated to `False` even for the genuinely correct, currently-linked project — a false-positive `REFUSED` on the one case the safety guard must never block.

Fixed in `read_linked_project_ref()` (`tools/pull_secondary_backup.py` L41):

```python
return LINKED_PROJECT_REF_FILE.read_text(encoding="utf-8").lstrip("﻿").strip()
```

Independently reproduced both the failure mode and the fix this turn: decoding the raw file content without `.lstrip("﻿")` and comparing to `EXPECTED_PROJECT_REF` returns `False`; applying the same `.lstrip("﻿").strip()` the shipped code uses returns `True`. The fix is correctly in place and the false-mismatch is closed.
