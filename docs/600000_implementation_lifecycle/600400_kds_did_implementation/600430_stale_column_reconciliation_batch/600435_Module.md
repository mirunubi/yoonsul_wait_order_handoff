## `0081`/`0099` Response Key Unification — A안 Fully Applied

The original `600434_ChangeContract.md` draft authorized only the `place_takeout_order()` parameter rename (`p_request_memo`→`p_memo`) while preserving `track_takeout_order()`'s and `get_kds_realtime_state()`'s response JSON output keys as `request_memo`. A separate Human decision (A안, 2026-07-11) confirmed during this workpacket's Stage 2 revisions unified the response-direction output keys with the same `memo` terminology, reasoned on a repo-wide search finding no consumer of the `request_memo` output key (`600432_Logic.md` §2.1). This was implemented in two passes:

1. `0081` L1142: `'request_memo', v_order.request_memo,` → `'memo', v_order.memo,`
2. `0099` L448: `'request_memo', o.request_memo` → `'memo', o.memo` — this second pass landed mid-Stage-5 verification (Claude Code independently caught a live/source mismatch at the exact moment this change was applied; see `600436_Verification.md` §1 for the race-condition detail and its resolution).

`0099`'s `get_staff_alert_feed()` output key was **not** part of this unification — it does not carry a `request_memo`/`memo`-named field, so no equivalent question applied to it.

## `place_takeout_order()` Parameter Rename Required a `DROP FUNCTION`

Renaming `p_request_memo`→`p_memo` on `place_takeout_order()` was implemented as:

```sql
drop function if exists catchmenu_store.place_takeout_order(
  uuid, uuid, jsonb, uuid, text, text, text, uuid, integer, timestamptz, text
);

create or replace function
  catchmenu_store.place_takeout_order(
  ...
  p_memo text default null,
  ...
```

immediately before the `create or replace function` block, rather than relying on `CREATE OR REPLACE FUNCTION` alone to rename the parameter.

**Blast-radius verification (Stage 5, independently reproduced — not taken from Codex's report):** a live query against `pg_proc.prosrc` across every `catchmenu_%` schema for any function body containing `place_takeout_order(` other than the definition itself returned zero rows. Source-level `grep` across all of `sql/migrations/*.sql` found only two non-definition references — `0096_schema_final_validation.sql` L227 (a function-existence check by name, unaffected by the parameter rename) and `0113_create_api_spec_docs.sql` (plain-text API documentation, not executable SQL). No live or source caller was broken by the drop-and-recreate.
