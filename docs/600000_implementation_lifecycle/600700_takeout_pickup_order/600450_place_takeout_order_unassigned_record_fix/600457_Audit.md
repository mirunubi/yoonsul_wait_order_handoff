## Findings

1. The scalar-variable redesign fully closes the record-unassigned defect class this workpacket targeted — confirmed via 6 independently re-executed scenarios, not 4, since the point-policy paths (Groups 5-6) were also exercised.
2. Three separate, pre-existing defects were confirmed this turn to block full end-to-end success for `place_takeout_order()`: `chk_session_type` (blocks any coupon-free, points-free call — likely the most common real path), stale `point_ledger` columns (blocks any points-usage call by a real customer, firing before either of the other two defects would be reached), and `discount_pct` (blocks any coupon-ID call, guest or member — a wider blast radius than `600451_Overview.md` §3 originally characterized). None of the three involves `v_customer`/`v_coupon` record access; none is a regression from this fix.
3. `register_waiting()` (`0115_create_waiting_pipeline_rpc.sql`) was independently confirmed to use the correct `session_type` value (`'WAITING'`, in the allowed list) for the same `order_sessions` table — this both proves the constraint itself is not the problem and gives strong, concrete evidence (`'TAKEOUT'`, already in the allowed list and matching `place_takeout_order()`'s own `order_type`) for what the fix should be.
4. `catchmenu_store.deduct_points()` — the function `place_takeout_order()` calls to actually spend points — was independently checked and confirmed to already use the correct `point_ledger` column names. The stale-column defect is contained to `place_takeout_order()`'s own inline balance-check query, not a wider systemic issue.
5. The three defects occupy non-overlapping line ranges within the same function and fire in a fixed, input-dependent order (points+customer → `point_ledger` first; coupon → `discount_pct`; neither → `chk_session_type`) — no evidence of interaction risk between fixing them together in one follow-up batch.
6. This turn's inability to observe the `log_diagnostic()` write persist inside the full failing `place_takeout_order()` call (the transaction aborts and rolls back on the later `chk_session_type` error, taking the earlier diagnostic write with it) is itself live, concrete evidence supporting the newly-adopted `000701` §41 (Universal Failure Audit Requirement) — without an internal `EXCEPTION` handler, any audit/diagnostic evidence written earlier in a function's execution vanishes if a later unhandled error aborts the whole call.

## Open Items Carried Forward

(a) **`chk_session_type` — `place_takeout_order()` inserts `'ONLINE'`, not an allowed value (`0012_create_pos_order_sessions.sql`).** Newly discovered this workpacket. Strong candidate fix: `'TAKEOUT'` (already allowed, matches the function's own `order_type`). Blocks the most common real-world path (no coupon, no points). Recommended as the **first** fix in a follow-up batch (see §5 priority analysis, `600456_Verification.md`).

(b) **`point_ledger` stale columns (`point_type`/`point_amount` → actual `transaction_type`/`points_change`) in `place_takeout_order()`'s own point-balance query, plus a stale `'USE'` literal (should be `'DEDUCT'`).** Newly discovered this workpacket. Contained to this one query — `deduct_points()` itself is unaffected. Recommended as the second fix in the same follow-up batch.

(c) **`discount_pct` / `'AMOUNT'`/`'PCT'` literal mismatch — carried forward from `600451_Overview.md` §3, scope corrected this turn.** Confirmed to block guest+coupon as well as member+coupon (not member+coupon only, as previously understood). Recommended as the third fix in the same follow-up batch, given no interaction risk with (a)/(b).

(d) **Coupon double-use race condition — carried forward from `600452_Logic.md` §6/`600454_ChangeContract.md` §6.2.** Unrelated to (a)-(c); separate concurrency concern, not addressed here.

(e) **`600451_Overview.md`/`600452_Logic.md` documentation-accuracy note** — `600451_Overview.md` §3's characterization of `discount_pct` as a "member+coupon" issue should be corrected to "any coupon-ID-provided call" in a future documentation pass, per Finding 2/Open Item (c) above. Not corrected in this Audit since it falls outside this workpacket's Allowed Files/documents.
